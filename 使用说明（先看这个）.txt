【一、先看这一句】

双击「设备诊断修复.exe」就能用 —— 单文件，最省事。
不想双击 exe 的，双击「请双击这个-设备诊断修复.bat」完全一样：
两者跑的是同一份脚本（zip 里 _program 那两个 ps1 就是公开的源码）。

不用安装，不用联网，不需要管理员权限。

体检这一步是「只读」的：只读取信息、生成报告，
不改注册表、不写任何盘、不卸载任何设备。

从 0.2.1 开始，它多了两个真正能"动手"的修复键（都要你亲手点）：
  · 给丢了盘符的数据分区分配一个盘符
  · 把被禁用掉的设备重新启用
两个动作在动手之前都会先把"改之前是什么样"写进留底文件，
菜单里「撤销上一次修复」可以原样放回去。

它仍然不格式化、不分区、不恢复数据、不刷固件 ——
那四件事是把小毛病变成全没了的四条路，不在这款工具的范围内。


【二、它解决什么问题】

一个设备不工作，原因一定落在某一条链的某一环上：

    物理接口 → 系统枚举 → 匹配驱动 → 驱动加载 → 设备功能
                                        ↓
                        磁盘 → 分区 → 卷 → 盘符

这条链上第一个断掉的地方，决定了你该做什么，
也决定了你不该做什么。

绝大多数"我的盘坏了"，真正断掉的是【中间那几环】，
而不是设备真的坏了：

  · 盘符丢了 —— 分区好好的，只是没分配盘符
  · 驱动没装 —— 系统完全认出了硬件，只是没有匹配的驱动
  · 设备被禁用 —— 没坏，只是被关掉了
  · 枚举卡住 —— 设备在，只是 Windows 没重新扫描

这几种，软件层零风险就能修好。
而真正坏了的（磁头、颗粒磨穿、主控掉固件），
再怎么重装驱动也没用，那时候要做的是别的决定。


【三、怎么用（五步）】

  1. 把出问题的那台设备插上，并保持插着。
     ↑ 这一步不能省。设备不在场，关于它的任何判断都是空的。

  2. 点左下角绿色的「全面体检」。几秒钟。

  3. 在左边点任意一行，右边会说清三件事：
       ① 它是什么问题
       ② 能不能修
       ③ 现在最该做什么

  4. 右边按钮变绿了，说明这一项软件能修，点它就行（详见第五节）。
     灰色就是不用修、或者软件修不了，右边会写清下一步做什么。

  5. 需要求助时，点「导出报告」，把整个文件发出去。
     报告在桌面上，叫「设备诊断报告.txt」。


【四、左边四个视图】

  重点      磁盘、卷，以及所有报了错的设备。先看这个。
            正常的系统设备（卷影服务、IDE 控制器之类）
            不进这个视图，免得把真正要看的那几条淹掉。

  全部设备  Windows 报上来的每一台设备，包括正常的。
            想确认"我的 U 盘到底有没有被识别"就看这里。

  只看问题  只留有警告或有错误的行。

  硬件      CPU、内存、显卡、主板、BIOS、硬盘健康、温度、风扇。
            这一页读的是「这台机器本身什么状况」，不是「哪块盘坏了」。
            它比其它视图慢两三秒（要多读一批硬件数据），所以点开才读。

列表最右一列是「状态」，前面还有一个符号：

  ✓  正常
  !  有问题，但多数能修
  ✕  确实有问题，而且可能修不了
  ·  只是信息（比如历史记录）


【五、修复：它能动手，但只动两种】

点中左边某一行，右下角那个按钮会自己变样子：

  绿色「修复这一项（可还原）」  这一项软件能修，点它
  灰色「这一项不需要修」        本来就是正常的
  灰色「这一项软件修不了」      得用别的办法，看右边写的「最该做什么」

只有两种问题会变成绿色：

  · 数据分区丢了盘符（L1）—— 给它分配一个空闲盘符，不动里面任何数据
  · 设备被禁用 —— 等同设备管理器里点一下「启用设备」

点下去之后发生四件事：

  1. 先弹确认框，写清「要做什么、对谁做」，你点「是」才动；
  2. 不是管理员，会先问你要不要以管理员身份重新打开；
  3. 动手之前，把「改之前是什么样」写进留底文件；
  4. 做完自动重新体检一遍，让你直接看到结果对不对。

反悔了怎么办：

  菜单「工具 → 撤销上一次修复」，把最近一次动作原样还原。
  每一次动作都记在「打开修复记录」里，可以随时翻。
  留底文件在：%APPDATA%\DeviceLens\fix\log.txt

灰色按钮不是"懒得修"，是这件事不该由软件替你决定：
格式化、重建分区表、恢复数据、刷固件、装下载站的驱动。
报告里会写清这一步该找谁，以及为什么不该在这里点。


【六、「层」是什么意思】

这是本工具最核心的东西。每一行都会标一个层：

  E2  枚举      Windows 完全看不到这台设备
  E3  匹配      设备看到了，但没有匹配的驱动（代码 28）
  E4  加载      驱动装上了，但启动不了（代码 10 / 12 / 31 / 52）
  E5  功能      驱动正常，那就该怀疑设备本身了
  L1  卷        分区是好的，只是没有盘符
  L2  分区表    没有分区，系统会让你「初始化磁盘」
  L3  文件系统  分区在，但读不出文件系统（RAW）
  L4  正常
  HW  硬件读数  CPU / 内存 / 显卡 / 主板 / 温度这一类的实测值

为什么这么分？因为「断在哪一层」直接决定「能不能修」：

  · 断在 E2 或 L1，软件通常零风险就能修好
  · 断在 E3，装对驱动就好，硬件是好的
  · 断在 E4，换驱动版本，通常能解决
  · 断在 E5，再折腾软件也没用 ——
    该去看线、看口、看供电，或者考虑送修


【七、几个最容易踩的坑，工具会提前拦住你】

  1. 「需要先初始化磁盘」
     别点。初始化会清掉分区表，里面有东西就再也读不出来了。
     这通常是分区表丢了，先做数据恢复，再谈修盘。

  2. 「需要格式化才能使用」
     别点。先看清是哪种问题（工具会给结论）。
     格式化之后，数据恢复的难度会翻好几倍。

  3. 「磁盘被写保护」
     有五种完全不同的原因：物理开关、卷只读、磁盘只读、
     注册表策略、闪存寿命耗尽自锁。
     不查清楚就照着网上教程改注册表，可能白改还删错东西。

  4. 设备管理器里的「代码 28」
     这不是"驱动丢了"，是"系统认识这块硬件，但没有匹配的驱动"。
     点「复制硬件 ID」，拿 VID/PID 去厂家官网找，比装万能驱动包靠谱。
     万能驱动包会把小毛病变成蓝屏。


【八、「重新识别」是什么】

等同于设备管理器里点一下「扫描检测硬件改动」。

  · 只让 Windows 重新找一遍设备
  · 不改任何设置、不卸载任何东西
  · 已经能用的设备不会掉
  · 有些设备会闪一下（比如 U 盘灯），正常

需要管理员权限。如果你现在不是管理员，
点这个按钮会提示你，并且可以一键以管理员身份重开。

什么时候该用它：
设备刚才还好好的，忽然在"此电脑"里不见了 —— 先点这个。


【九、盘符占用看板】

菜单「工具 → 盘符占用看板 (A–Z)」。

一眼看出 26 个字母谁占了、谁空着、谁被旧记录占着。

"为什么我的 D 盘用不了" —— 这里直接给答案，
不用去翻磁盘管理。


【十、历史设备】

菜单最下面的「历史设备」按钮。

列出"以前在这台电脑上插过、现在没插"的设备记录。

它们不影响使用，也不占资源。
这个版本只列出来看，不做清理。


【十一、它永远不会做的事（有了修复键也一样）】

  格式化磁盘
  新建或删除分区
  恢复数据
  刷固件 / 用量产工具修 U 盘
  安装从下载站抓来的驱动

前四件，是把"小毛病"变成"全没了"的四条路。
最后一件，是把小毛病变成蓝屏的最快方式。

有了修复键之后，这条线没有变。
这些事不是做不到，是不该由"一键修复"来做。
系统自带的磁盘管理和专业数据恢复工具做得更好。


【十二、读不到 SMART 这件事得说清】

U 盘、内存卡、廉价硬盘盒，绝大多数读不到 SMART 健康数据。
不是工具不行，是这类设备本身就没有把健康数据暴露出来
（USB 桥接芯片不透传 ATA 命令）。

所以本工具不会给你编一个"健康度 87%"。
能给的结论，都来自实际能读到的证据：
错误码、分区链是否完整、文件系统能不能读、盘符对不对得上。

宁可说"这台设备读不到健康数据"，也不编。

同样的规矩也用在温度和风扇上：
很多台式机主板根本不通过 ACPI 暴露传感器，取回来是空的。
那时候工具会直接写「这台机器不提供」，而不是给一个假数字。
要看真实温度，进 BIOS 的 Hardware Monitor 页最准。


【十三、报告里有什么】

桌面上的「设备诊断报告.txt」，六段：

  一、有问题的项目    逐条三段式：是什么 / 能不能修 / 该做什么
  二、四层视图        设备 → 磁盘 → 卷 → 盘符，一眼看出断在哪
  三、盘符占用 A–Z    为什么某个字母用不了
  四、非正常设备明细  错误码 + 硬件 ID
  五、硬件读数        CPU 频率与负载 / 内存条 / 显卡驱动 / 主板 / BIOS / 盘健康 / 温度 / 风扇
  六、怎么反馈        需要帮忙时怎么描述现象

整个文件发出即可，里面没有隐私信息
（只有设备型号、硬件 ID、卷标）。


【十四、常见问题】

Q：exe 和 bat 有什么区别？我该用哪个？
A：随便哪个都行，内容一模一样。
   exe 是单文件，双击就走，最省事，也最不容易被系统策略拦住；
   bat 是脚本版，好处是你随时能打开 _program 里的源码，
   看它到底做了什么 —— 这是它敢称「透明」的原因。
   exe 旁边那个「设备诊断修复.exe.config」别删：它管高分屏清晰度，
   少了程序照样能跑，只是字会发虚。

Q：双击 exe / bat 都没反应？
A：先确认是从硬盘上双击的，不要在压缩包里直接双击。
   用 bat 的话，_program 文件夹必须和它放在一起，只拷 bat 一个不行。
   如果已经解压了，右键 → 以管理员身份运行试一次。

Q：杀毒软件说 exe 有问题？
A：这个 exe 是把同一份脚本（中英双语界面 + 只读体检 + 两种可撤销的修复）
   打包成的单文件，自身没有联网、没有自启、不往系统目录写东西。
   这类「脚本打包器」被启发式引擎误判很常见。
   zip 里同时给了 bat 和完整源码：不放心就删掉 exe 用 bat，
   或者直接打开 _program 里那两个 ps1 一行行看。

Q：提示"这个目录里还有 USB / 串口 一键修复 的文件"？
A：两款工具不能放在同一个文件夹，会互相覆盖。
   请把本程序解压到它自己的文件夹里。

Q：它说我的盘"分区无盘符"，怎么修？
A：先确认那是个数据分区。EFI 启动分区、MSR 保留分区、
   扩展分区容器本来就不该有盘符，工具不会把它们报成问题
   （v0.1.0 会报，那是误判，v0.2.0 已改）。
   真是数据分区没有盘符：点中那一行，右下角按钮会变绿，点它就行
   （详见第五节）。不想用一键，也可以磁盘管理 → 右键那个分区 →
   「更改驱动器号和路径」→ 添加。

Q：报告里的"层"我看不懂。
A：只看最右边「状态」和右边面板的③就够了。
   层是给要往下深究的人准备的。

Q：为什么不帮我全修了？
A：能安全还原的它已经修了：分配盘符、重新启用被禁用的设备。
   其余的不是「没写」，是不该由一个按钮替你决定 ——
   格式化、重建分区表、恢复数据、刷固件，这四件事点错就不可逆，
   所以它只负责告诉你该找谁、为什么不在这里点。
   后续会继续加：拒绝访问修复、钉住盘符、修失效的歌单路径、
   挂载到文件夹，每一个都同样先留底、可撤销。

【十六、与「USB / 串口 一键修复」的关系】

那是另一款工具，管两件事：串口设备把 COM 端口号固定住、
让 Windows 死活认不出的 USB 设备重新被识别。

本作管的是：任何接在电脑上的设备，先看清断在哪一层。

两款是彼此独立的程序，必须放在各自的文件夹里。

COM 端口号的事，请用前作；本工具只在结论里提示，不重复实现。
